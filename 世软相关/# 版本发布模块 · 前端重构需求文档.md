
  

本文档依据现有前端真实行为整理，供从未接触旧项目的前端工程师独立实现本模块。描述的是**用户能看到和做到的行为**，不是旧文件结构。

  

约定：

  

- 后台为多 Tab iframe 壳（Layui miniTab 同类能力即可）。

- 本模块页面标题在旧系统中为「系统发布」；业务上即「版本发布」。

- 文中「现状缺口」表示代码里存在、但当前 UI 走不到或行为不完整的能力。重构时默认**按真实行为实现**；若产品要求补齐，已单独标出。

# 页面结构

  

本模块共 **3 个页面 + 1 个弹层**。编辑与创建共用同一套表单，用模式区分。

  

## 1. 版本列表页

  

**路由建议**：`/release`（旧路径 `GET /admin/release/index`）

  

**职责**：版本的查询、浏览、创建入口、复制 / 发布 / 撤回 / 删除。

  

**布局（自上而下）**：

  

```

┌─────────────────────────────────────────────┐

│ 搜索区（fieldset「搜索信息」）                 │

│  产品 | 版本号 | 修改时间(起-止) | 类型 | 状态  │

│  [搜索] [重置]                                │

├─────────────────────────────────────────────┤

│ 工具栏：[创建版本]                             │

├─────────────────────────────────────────────┤

│ 表格（分页）                                   │

│  产品 | 版本号 | 类型 | 升级类型 | 状态        │

│  | 最后修改时间 | 最后修改人 | 操作            │

└─────────────────────────────────────────────┘

```

  

列表是模块首页，由侧边菜单进入。

  

## 2. 选择发布产品弹层

  

**打开方式**：列表工具栏「创建版本」→ 居中 iframe / 弹层（旧实现约 60% × 60%，可最大化、点遮罩关闭）。

  

**标题**：选择发布产品

  

**布局**：

  

```

┌─ 产品分类 A（默认展开）──────────────────────┐

│  [产品卡片] [产品卡片] [产品卡片] ...          │

│  名称 + 图片 + 按钮「创建版本 ▾」              │

└─────────────────────────────────────────────┘

┌─ 产品分类 B（默认收起）──────────────────────┐

│  ...                                         │

└─────────────────────────────────────────────┘

```

  

卡片栅格：大屏约 4 列，中屏约 3 列。无图时用占位图。

  

## 3. 版本表单页（创建 / 编辑）

  

**创建路由**：`/release/create?productId={id}&type={1|2}`  

（旧路径 `GET /admin/release/store/{product_id}/{type}`）

  

**编辑路由**：`/release/:id/edit`  

（旧路径 `GET /admin/release/show/{id}`）

  

**打开方式**：后台新 Tab。创建 Tab 标题为「创建正式版」或「创建测试版」；编辑 Tab 标题为「编辑正式版」或「编辑测试版」。

  

**布局**：

  

```

产品（禁用） | 类型（禁用） | 版本号 *

升级类型     | 升级方式     | 版本说明

  

版本要求 *

  Tab：安装要求 | 升级要求

  每行：程序服务 | 版本条件 | 版本号(或区间) | +/-

  

程序文件 *   [上传...] [+] [-]

发版文档     [上传...] [+] [-]

  

（仅编辑）最后修改人 | 最后修改时间   ← 只读

  

[保存] [取消]

```

  

产品、类型在创建时由入口带入，全程不可改。

  

## 页面关系（结构，不是操作步骤）

  

| 页面 | 父级 | 子级 |

|------|------|------|

| 列表 | 菜单 | 选择产品弹层；创建/编辑 Tab |

| 选择产品弹层 | 列表 | 无；选完后打开创建 Tab 并关闭自身 |

| 创建表单 | 列表（新 Tab） | 无 |

| 编辑表单 | 列表（新 Tab） | 无 |

  

**现状缺口**：列表操作列没有「编辑 / 详情」。编辑页接口和模板存在，但用户从列表进不去。重构若要与线上一致，可不做编辑入口；若要补齐完整模块，应在操作列恢复「编辑」，跳转编辑 Tab。

# 页面流程

  

## 主流程：创建并保存版本

  

```

用户从菜单进入列表

→ 点「创建版本」

→ 弹层按分类展示产品

→ 点某产品「创建版本」

→ 下拉：创建正式版 / 创建测试版（受权限裁剪）

→ 关闭弹层，打开「创建正式版/测试版」Tab

→ 填写版本号、升级类型/方式、版本说明

→ 配置安装要求（可空）、升级要求（至少 1 条有效）

→ 上传至少一个程序文件；发版文档可选

→ 点保存

→ 校验通过后提交

→ 成功提示，约 1 秒后关闭当前 Tab，回到列表

```

  

取消：关闭当前 Tab，不提交、不提示。

  

## 查询流程

  

```

列表改筛选条件 → 点搜索 → 表格从第 1 页按条件重载

点重置 → 清空所有条件并自动再搜一次（回到第 1 页）

改分页条数 / 翻页 → 带当前筛选条件请求

```

  

## 行操作流程（复制 / 发布 / 撤回 / 删除）

  

```

点行按钮

→ 确认框：「是否要{操作}{产品名}{正式版|测试版}V{版本号}」

→ 确认后请求接口

→ 用返回 msg 提示（成功绿、失败红，约 3 秒）

→ 成功则刷新整个列表页；失败只关确认框

```

  

复制成功后列表会出现一条新的「未发布」记录，**不会**自动打开编辑页。

  

## 编辑流程（代码存在、列表无入口）

  

```

打开编辑页（若补齐入口：列表点编辑）

→ 回填表单

→ 修改后保存 → 更新接口

→ 成功提示并关 Tab

```

  

## Tab / 弹层通信（实现约束）

  

选择产品弹层在 iframe 内，不能自己开后台 Tab，必须通知父页面：

  

```

弹层 postMessage({ url: 创建页地址, title: 「创建正式版」或「创建测试版」 })

列表页收到后：关闭所有弹层，再用壳的 openTab(url, title) 打开创建页

```

# 页面状态

  

## 1. 版本业务状态（列表行、接口 `status`）

  

| 值 | 文案 | 行操作 |

|----|------|--------|

| 1 | 未发布 | 显示「发布」；可复制、可删除 |

| 2 | 已发布 | 显示「撤回」；可复制、可删除 |

| 3 | 已撤回 | 显示「发布」；可复制、可删除 |

  

前端用 `status === 2` 切换发布/撤回，其它状态都当「未发布侧」处理。

  

**真实行为**：已发布记录前端仍可删除，操作列不禁用。

  

## 2. 版本类型 `type`

  

| 值 | 文案 | 出现位置 |

|----|------|----------|

| 1 | 正式版 | 筛选、表格、创建入口、确认文案、表单 |

| 2 | 测试版 | 同上 |

  

## 3. 升级类型 `upgrade_type`

  

| 值 | 文案 |

|----|------|

| 1 | 可选升级 |

| 2 | 必须升级 |

  

## 4. 升级方式 `upgrade_auto`

  

| 值 | 文案 |

|----|------|

| 1 | 自动升级 |

| 2 | 手动升级 |

  

## 5. 列表页 UI 状态

  

| 状态 | 表现 |

|------|------|

| 首次进入 | 无筛选，拉第一页，每页 15 条 |

| 查询中 | 表格 loading |

| 有数据 | 渲染行 |

| 无数据 | 空表（不另做空态页） |

| 接口失败 | 表格按 `msg` 提示；`code !== 0` 视为失败 |

| 操作确认中 | 确认框；确认后请求，成功整页刷新 |

  

## 6. 表单页模式

  

| 模式 | 来源 | 差异 |

|------|------|------|

| 创建 | 产品弹层 | 空表；无「最后修改人/时间」；保存走创建接口 |

| 编辑 | `/show/:id` | 回填；展示修改人/时间（只读）；保存走更新接口 |

  

编辑回填字段：`version`、`remark`、`upgrade_type`、程序文件、发版文档、安装要求、升级要求。

  

**现状缺口**：编辑页**不回填** `upgrade_auto`，下拉会落到该产品的默认值（见特殊规则），而不是库里的值。

  

## 7. 单条文件上传状态（前端本地）

  

| 值 | 含义 | UI |

|----|------|----|

| 1 | 上传完成 | 显示文件名，可删行 |

| 2 | 未上传 | 显示上传按钮 |

| 3 | 上传中（进度展示） | 进度条；隐藏「−」 |

| 4 | 失败/取消 | 回到可上传；提交时仍会因无 `file_id` 拦截（程序文件） |

| 5 | 分片上传中 | 同 3，显示进度 |

  

同一行在完成前 `file_id` 为空。

  

## 8. 产品形态（决定表单控件，不是列表状态）

  

由产品 `code` 决定，见「特殊业务规则」。表单进入时即定型，用户不能切换。

# API清单

  

统一响应：

  

```json

{ "code": 0, "msg": "文案", "data": {} }

```

  

- `code === 0`：成功

- 其它：失败，把 `msg` 给用户

- 写操作 Header：`X-CSRF-TOKEN`

- 无权限 Ajax：`{ "code": 1, "msg": "您没有权限执行该操作" }`

- 无权限打开页面：跳转 403 页「您没权限访问该页面！」

  

路径按旧系统列出，重构时可换成 REST，但**入参、出参语义必须对齐**。

  

---

  

## API-1 版本列表

  

- **方法 / URL**：`GET /admin/release/index`

- **调用时机**：进入列表、搜索、重置、翻页（带 Ajax 头；同 URL 无 Ajax 头返回 HTML 列表页）

  

**Query**：

  

| 参数 | 必填 | 说明 |

|------|------|------|

| page | 否 | 页码，默认 1 |

| limit | 否 | 每页条数，默认 15 |

| product_id | 否 | 产品 ID，空=全部 |

| version | 否 | 版本号模糊 |

| start_date | 否 | 修改时间起，`YYYY-MM-DD HH:mm:ss` |

| end_date | 否 | 修改时间止，同上 |

| type | 否 | `1` / `2`，空=全部 |

| status | 否 | `1` / `2` / `3`，空=全部 |

  

**响应（表格依赖）**：

  

| 字段 | 说明 |

|------|------|

| code | 0 成功 |

| msg | 提示 |

| total | 总条数（不是 `count`） |

| data | 数组 |

  

`data[]` 至少包含：

  

| 字段 | 说明 |

|------|------|

| id | 版本 ID |

| version | 版本号 |

| type | 1 / 2 |

| upgrade_type | 1 / 2 |

| status | 1 / 2 / 3 |

| updated_at | 最后修改时间 |

| operator | 最后修改人 |

| product.name | 产品名称 |

## API-2 产品选择页数据

  

旧实现是 `GET /admin/release/list` 直接出 HTML。重构可改为：

  

- 页面接口返回分类树；或

- 独立 `GET` 返回 `{ categories: [{ name, products: [{ id, name, image }] }] }`

  

产品卡片需要：`id`、`name`、`image`（空则占位图）。

## API-3 打开创建页所需字典

  

旧实现随 HTML 注入。前端需要：

  

| 数据 | 用途 |

|------|------|

| 产品列表 `id + name` | 禁用的产品下拉（回显名称） |

| 当前产品 `id + code + name` | 特殊产品 UI |

| 程序服务列表 `app + app_name` | 版本要求下拉 |

  

路径参数：`product_id`、`type`（1 或 2）。

  

---

  

## API-4 创建版本

  

- **方法 / URL**：`POST /admin/release/store/{product_id}/{type}`

- **Body**（`application/x-www-form-urlencoded` 或等价嵌套对象）：

  

| 字段 | 说明 |

|------|------|

| product_id | 与路径一致 |

| type | 与路径一致，1 / 2 |

| version | 版本号 |

| remark | 版本说明 |

| upgrade_type | 1 / 2 |

| upgrade_auto | 1 / 2 |

| install_require[i].id | 新建传空 |

| install_require[i].require_app | 程序服务标识（产品 `app` 或特殊产品 `code`） |

| install_require[i].version_condition | `ge` / `le` / `between` |

| install_require[i].version | 非区间 |

| install_require[i].version_min | 区间最小 |

| install_require[i].version_max | 区间最大 |

| upgrade_require[i].* | 同上 |

| program-files[i].id | 新建传空 |

| program-files[i].file_id | 上传接口返回的文件 ID |

| release-doc[i].id | 新建传空 |

| release-doc[i].file_id | 发版文档文件 ID，未上传可为空 |

  

**提交策略（必须一致）**：

  

- 安装要求：仅提交 `require_app` 非空的行。

- 升级要求：当前数组里的行全部提交（含用户填完的行）。

- 程序文件、发版文档：每一行都提交。

  

成功 `msg` 示例：`创建版本成功！`。前端只判断 `code` 和 `msg`。

  

---

  

## API-5 打开编辑页

  

- **方法 / URL**：`GET /admin/release/show/{id}`

- 旧实现出 HTML。重构需等价数据：

  

版本头：`id, product_id, type, version, remark, upgrade_type, upgrade_auto, operator, updated_at`

  

程序文件 / 发版文档每项：`id`（关联记录 ID）、`file_id`、`original_name`

  

安装 / 升级要求每项：`id, require_app, version_condition, version, version_min, version_max`

  

不存在时旧行为：跳转错误页「该发布不存在！」（404）。

  

---

  

## API-6 更新版本

  

- **方法 / URL**：`POST /admin/release/update/{id}`

- **Body**：与创建相同；`product_id`、`type` 取当前记录，不可被用户改。

- 前端只用 `code`、`msg`。

  

---

  

## API-7 发布 / 撤回 / 复制

  

- **方法 / URL**：`GET /admin/release/edit/{id}/{status}`

- **status**：`2` 发布 · `3` 撤回 · `4` 复制

- 成功 `msg`：`发布成功！` / `撤回成功！` / `复制成功！`（前端直接展示接口 `msg`）

  

---

  

## API-8 删除

  

- **方法 / URL**：`DELETE /admin/release/destroy/{id}`

- 成功 `msg`：`删除成功！`

  

---

  

## API-9 上传文件

  

- **方法 / URL**：`POST /admin/upload`

- **Content-Type**：`multipart/form-data`

  

| 字段 | 说明 |

|------|------|

| file | 整个文件，或当前 2MB 分片 |

| md5 | 文件 MD5 |

| ext | 扩展名（文件名最后一段） |

| original_name | 原始文件名 |

| page | 当前分片，从 1 开始；小文件传 1 |

| total_page | 分片总数；小文件传 1 |

  

**data**：

  

| 字段 | 何时有 | 前端用法 |

|------|--------|----------|

| id | 完成时 | 写入该行 `file_id` |

| original_name | 通常都有 | 展示文件名 |

| status | 通常都有 | `1` 完成，`3` 分片未结束 |

| progress | 分片过程 | 进度百分比 |

| oss_key | 分片过程 | 前端可存，**保存版本时不提交** |

  

`code !== 0`：该行标失败。同一文件若服务端已有相同 MD5，可能直接 `status=1` 并返回已有 `id`。

  

---

  

## API-10 菜单（模块入口，非本模块内部）

  

`GET /admin/dashboard/init` 返回侧边菜单。本模块列表 href 指向列表页。无菜单权限则用户看不到入口。

  

列表页的产品下拉，旧实现随 HTML 注入 `products: [{id, name}]`。重构可复用产品字典接口。

# 数据模型

  

## Product（产品）

  

| 字段 | 说明 |

|------|------|

| id | 产品 ID |

| name | 展示名 |

| image | 卡片图，空则占位 |

| code | 产品编码，决定表单特殊形态 |

  

已知特殊 `code`：

  

- `CloudStoreKiosk` → 文案「云管家自助机」

- `CloudStorePOS` → 文案「云管家前台」

- `StoreServiceScript`

- `OtherScript`

  

## ProductCategory（产品分类）

  

| 字段 | 说明 |

|------|------|

| name | 折叠面板标题 |

| products | 该分类下产品 |

  

## ProductRequire（程序服务字典）

  

| 字段 | 说明 |

|------|------|

| app | 值，写入 `require_app` |

| app_name | 下拉文案 |

  

## Release（版本列表行 / 表单头）

  

| 字段 | 说明 |

# 表单校验规则

  

全部在点「保存」时一次性校验，失败 `toast` 第一条错误并中止提交。无失焦校验、无字数/正则限制。

  

## 头部

  

| 字段 | 规则 | 提示原文 |

|------|------|----------|

| 版本号 | trim 后非空 | 请输入版本号！ |

| 版本说明 | trim 后非空 | 请完善升级说明！ |

  

产品、类型禁用，不校验。升级类型、升级方式靠默认选中，无单独提示。

  

## 安装要求

  

只校验 `require_app` **已填写**的行；空行跳过且不提交。

  

对第 `N` 条（N 从 1）：

  

| 条件 | 提示 |

|------|------|

| `require_app` 空 | 请选择版本安装要求的第N个程序服务！ |

| `version_condition` 空 | 请选择版本安装要求的第N个程序服务的版本条件！ |

| 条件不是 `between` 且 `version` 空 | 请输入版本安装要求的第N个程序服务的版本号！ |

| `between` 且最大版本空 | 请输入版本安装要求的第N个程序服务的最大版本号！ |

| `between` 且最小版本空 | 请输入版本安装要求的第N个程序服务的最小版本号！ |

| `between` 且 min > max | 版本安装要求的第N个程序服务的最小版本号不能大于最大版本号！ |

| `between` 且 min == max | 版本安装要求的第N个程序服务的最小版本号不能等于最大版本号！ |

  

版本比较：按 `.` 分段，缺段当 `0`，逐段 `parseInt` 比较。不校验是否合法版本格式（`1.2.3` 与 `abc` 都可输入）。

  

## 升级要求

  

规则与安装要求相同，文案把「安装」换成「升级」。

  

**真实行为**：默认那条空行也会走升级要求校验。用户不填升级要求直接保存，会提示选第 1 个程序服务。因此升级要求实际上至少要完整填 1 条。

  

## 文件

  

| 字段 | 规则 | 提示 |

|------|------|------|

| 程序文件每一行 | `file_id` 非空 | 请上传第N项程序文件！ |

| 发版文档 | 不校验是否上传 | — |

  

上传中（无 `file_id`）点保存，程序文件会按上面提示失败。

  

## 接口校验失败

  

把接口 `msg` 原样提示，例如：版本号已存在、升级说明必填等。前端不必预实现这些规则，但应能展示。

# 权限规则

  

## 登录与路由

  

模块所有页面、接口需登录。未授权：

  

- 页面 → 403「您没权限访问该页面！」

- 接口 → `{ code: 1, msg: "您没有权限执行该操作" }`

  

超管（`supervision == 1`）视为拥有全部权限。

  

## 菜单

  

能否看到「系统发布 / 版本发布」由菜单接口决定。没有菜单项就不能从导航进入列表。

  

## 前端真正做了的权限（必须实现）

  

仅出现在「选择产品」下拉：

  

| 权限 key | 效果 |

|----------|------|

| `release_formal` | 显示「创建正式版」 |

| `release_test` | 显示「创建测试版」 |

  

都没有：按钮点开后没有可选项（列表「创建版本」按钮本身仍显示）。

  

超管两项都显示。

  

## 前端没有做的权限（不要自行加，除非产品要求）

  

- 列表「创建版本」

- 复制 / 发布 / 撤回 / 删除

- 保存

  

这些只靠后端路由权限。无权限时弹出接口 `msg` 即可。

# 特殊业务规则

  

## 1. 按产品 code 裁剪表单

  

先算 `special = code ∈ { CloudStoreKiosk, CloudStorePOS }`。

  

### 升级类型

  

| 产品 | UI |

|------|----|

| `CloudStoreKiosk`、`CloudStorePOS`、`StoreServiceScript`、`OtherScript` | 只读一项：必须升级（`upgrade_type=2`），默认勾选 |

| 其它 | 可选升级（默认）+ 必须升级 |

  

### 升级方式

  

| 产品 | UI |

|------|----|

| `special === true`（Kiosk / POS） | 只有「自动升级」，默认选中 |

| 其它 | 「自动升级」+「手动升级」，**默认手动升级** |

  

### 版本要求「程序服务」

  

| 产品 | UI |

|------|----|

| Kiosk / POS | 复选框，值为产品 `code`，标题为「云管家自助机」或「云管家前台」，默认勾选；对应 `require_app` 预填 `code`；取消勾选则该行 `require_app` 变空 |

| 其它 | 可搜索下拉，选项来自程序服务字典；空选项「请选择程序服务」 |

  

### 要求行 +/-

  

Kiosk / POS：**隐藏**（不能增删行，安装/升级各保持 1 行）。  

其它：显示；多于 1 行时显示「−」。

  

## 2. 发布 / 撤回 / 复制的语义（前端侧）

  

前端只传 `status`，不组其它业务数据。

  

- 发布 `2`：未发布、已撤回可点。

- 撤回 `3`：仅已发布可点。

- 复制 `4`：任意状态可点；生成一条未发布副本，版本号等与源相同。

  

## 3. 上传策略（必须按此实现）

  

1. 用户选文件后先出 loading「读取文件中」。

2. 按 **2MB** 切片计算整个文件 MD5（SparkMD5 同类算法）。

3. **体积 ≥ 3MB**：分片上传，每片 2MB；用定时器约 **1 秒** 一片；用返回的 `progress` 更新进度条；`status=1` 停止。

4. **体积 < 3MB**：整文件一次上传，`page=1`，`total_page=1`。

5. 不限制扩展名、MIME。

6. 程序文件、发版文档同一套上传，只是文案和提交字段名不同。

  

## 4. 确认文案拼接

  

```

是否要 + 发布|撤回|复制|删除 + {产品名} + 正式版|测试版 + V + {version}

```

  

例：`是否要发布云管家前台正式版V1.2.3`

  

## 5. 创建成功不刷新列表

  

保存成功只关表单 Tab。用户回到列表看到的仍是打开创建前的数据，需手动刷新或再搜索。行操作（发布等）则会整页刷新。

  

## 6. 安装要求可空、升级要求实际必填

  

安装要求全部空行 → 不传 `install_require`，可以通过前端校验。  

升级要求空行 → 通不过。

  

## 7. 编辑页 `upgrade_auto` 不回填

  

若实现编辑，与旧行为对齐则不要用接口值覆盖升级方式（会显示产品默认值）。若作为缺陷修复，应回填接口值，并在需求评审中确认。

# 页面交互细节

  

## 列表搜索区

  

- 产品、类型、状态：下拉，第一项「全部」，值为空。

- 版本号：placeholder「请输入版本号」。

- 修改时间：同一日期时间范围组件，左「开始日期」右「结束日期」，格式 `YYYY-MM-DD HH:mm:ss`。

- 搜索：主按钮；重置：次按钮 + 垃圾桶图标。

- 重置清空：`product_id, version, start_date, end_date, type, status`，然后触发一次搜索。

  

## 列表表格

  

- 风格：行线表。

- 操作列最小宽度约 150px，居中。

- 按钮：复制、发布/撤回为普通小按钮；删除为危险红。

- 无批量选择、无排序点击。

  

## 创建版本弹层

  

- 宽高约 60% × 60%，遮罩 0.2，可最大化，点遮罩关闭。

- 窗口 resize 时旧代码会把弹层拉满，重构可改为响应式居中，不必强行 `full`。

- 分类折叠：第一项 `open`，其余收起。

- 产品图 120×120。

- 「创建版本」是下拉触发器，不是直接跳转。

- 选正式/测试后：父页关弹层并开 Tab，不再留在弹层里。

  

## 表单

  

- 必填项 label 后红 `*`：版本号、版本要求、程序文件。版本说明前端必填但 label **没有**红星（按旧 UI）。

- 禁用下拉仍要显示当前产品名、类型名。

- 切换「区间范围」立刻把该行右侧换成两个框：placeholder「开始版本」「结束版本」；其它条件为一个框「请输入版本号」。

- 改版本条件、改程序服务、改版本号输入，都写回内存数组再重渲染该 Tab 内容（条件切换会重绘整行）。

- 「+」在该组末尾加一行空数据。「−」删当前行，至少留 1 行。

- 上传「+」「−」规则相同；上传中（status=3）不显示「−」，防止删掉进行中的任务。

- 未上传：按钮「上传程序文件」或「上传发版文档」。

- 已上传：文件名灰色描边标签，该行不再显示上传按钮（要换文件需删行再加）。

- 上传中：进度条 + 「上传进度：xx%」。

- 选文件后到 MD5 算完：全屏 loading「读取文件中」。

- 点保存：`正在提交，请稍后`（带遮罩，不自动关）；结束再关，再出成功/失败 toast。

- 成功：icon 成功，约 1 秒后关 Tab。

- 失败 / 校验失败：icon 失败，停留在当前页。

  

## 行操作弹窗

  

- `confirm`，icon 问号，标题「提示」。

- 成功 toast 约 3 秒，期间不可点遮罩关；结束后成功则 `reload` 列表页。

  

## 后台 Tab

  

- 创建/编辑在新 Tab，不覆盖列表。

- 取消 = 关当前 Tab。

- 保存成功 = 关当前 Tab。

- 列表始终可回。

## 建议的实现顺序

  

1. 字典：类型、状态、升级类型、升级方式、版本条件。

2. 列表 + 筛选 + 分页。

3. 行操作确认 + 四个接口。

4. 选产品弹层 + 权限下拉 + 开 Tab。

5. 普通产品表单 + 校验 + 创建。

6. 上传（小文件）再分片。

7. 特殊产品 UI 裁剪。

8. 编辑回填与更新（若本次重构包含编辑入口）。
