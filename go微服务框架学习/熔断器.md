**熔断器（Circuit Breaker）** 是一种用于提升系统稳定性和容错能力的机制。它的核心作用是：**防止系统在调用失败时无限制地重试，避免故障蔓延，保护系统其他部分正常运行。**

# 熔断器的三种状态

熔断器就像电路开关，有三种典型状态：

| 状态                 | 含义                                   |
| ------------------ | ------------------------------------ |
| **关闭（Closed）**     | 正常调用下游服务，即使有失败，也只记录失败次数。             |
| **开启（Open）**       | 达到失败阈值后，熔断器“断开电路”，不再调用下游服务，直接返回错误。   |
| **半开启（Half-Open）** | 在一段时间后允许部分请求试探性地调用下游服务，如果成功就恢复为关闭状态。 |
# 常见熔断器的使用

## `gobreaker`

安装： `go get github.com/sony/gobreaker`

```go
  st := gobreaker.Settings{
    Name:        "test breaker",
    MaxRequests: 3,
    Interval:    10 * time.Second,
    Timeout:     5 * time.Second,
    ReadyToTrip: func(counts gobreaker.Counts) bool {
      failRequestRate := float64(counts.TotalFailures) / float64(counts.Requests)
      return counts.Requests >= 5 || failRequestRate > 0.6
    },
  }
  cb := gobreaker.NewCircuitBreaker(st)
```

**代码解释**：
- **`Name`** 给熔断器一个名字，便于日志记录或调试。
- **`MaxRequests`** 熔断器在**半开启（Half-Open）状态**下，允许的“试探性请求”数量。只有都请求成功了，熔断器才会恢复到关闭状态
- **`Interval`** 统计窗口周期。每隔这个时间，会重置一次请求和失败计数（`Counts`）。只有在关闭状态才起效。类似于**固定窗口算法**的窗口大小。
- **`Timeout`** 熔断器进入**开启（Open）状态**后的持续时间。超过这个时间，会转为半开启状态，允许“试探性请求”执行。
- **`ReadyToTrip`** 判断熔断器**开启**的条件

# 简单熔断器的实现

```go
type State int

var (
  ErrCirclebreakerOpen = errors.New("circle breaker is open")
)

const (
  Close State = iota
  Open
  HalfOpen
)

type Option func(*CircuitBreaker)

type CircuitBreaker struct {
  Name           string
  state          State
  successRequest int
  failRequest    int
  failureThresh  int           //  The number of consecutive failure required to switch to the open state.
  successThresh  int           // The number of consecutive successes required to switch to the close state.
  timeout        time.Duration // duration of open
  lastFailTime   time.Time
  mu             sync.Mutex
}

func WithTimeout(timeout time.Duration) Option {
  return func(cb *CircuitBreaker) {
    cb.timeout = timeout
  }
}

func NewCircuitBreaker(successThresh int, failureThresh int, opts ...Option) *CircuitBreaker {
  b := &CircuitBreaker{
    state:          Close,
    successRequest: 0,
    failRequest:    0,
    successThresh:  successThresh,
    failureThresh:  failureThresh,
    timeout:        time.Minute,
  }

  for _, opt := range opts {
    opt(b)
  }
  
  return b
}

func (cb *CircuitBreaker) Execute(fn func() (any, error)) (any, error) {
  // check state
  cb.mu.Lock()
  switch cb.state {
  case Open:
    if time.Since(cb.lastFailTime) > cb.timeout {
      cb.state = HalfOpen
      cb.failRequest = 0
      cb.successRequest = 0
    } else {
      cb.mu.Unlock()
      return nil, ErrCirclebreakerOpen
    }
  case Close:
  case HalfOpen:
  }
  cb.mu.Unlock()
  
  res, err := fn()

  cb.mu.Lock()
  defer cb.mu.Unlock()

  if err != nil {
    cb.lastFailTime = time.Now()
    cb.failRequest += 1
    switch cb.state {
    case HalfOpen:
      cb.state = Open
    case Close:
      if cb.failRequest >= cb.failureThresh {
        cb.state = Open
        cb.successRequest = 0
        cb.failRequest = 0
      }
    }
    return nil, err
  } else {
    cb.successRequest += 1
    switch cb.state {
    case HalfOpen:
      if cb.successRequest >= cb.successThresh {
        cb.state = Close
      }
    case Close:
      cb.failRequest = 0
    }
    return res, nil
  }
}
```

### ✅ 1. 明确状态机逻辑（三态模型）

熔断器通常有三种状态：

|状态|说明|
|---|---|
|**Closed**|一切正常，允许请求。连续失败达到阈值后转为 `Open`。|
|**Open**|熔断中，拒绝所有请求。等待一段时间（`timeout`）后自动进入 `HalfOpen`。|
|**HalfOpen**|试探状态，允许少量请求（通常一个），如果成功达到阈值转为 `Closed`，否则回 `Open`。|

---

### ✅ 2. 成功/失败统计与阈值判断

- `failureThresh`：失败多少次才进入 Open 状态。
    
- `successThresh`：在 HalfOpen 状态下，连续成功多少次才算恢复。
    
- 在 Close 状态下成功时应 **重置失败计数**，避免陈年失败影响当前状态判断。
    

---

### ✅ 3. Open 状态超时后自动切换为 HalfOpen

- 用 `lastFailTime` 记录上次失败的时间。
    
- 到达 `timeout` 后才允许探测请求（进入 HalfOpen）。
    

---

### ✅ 4. HalfOpen 只允许一次探测（关键并发控制）

- 在高并发环境中，**必须限制 HalfOpen 只放行一个请求**：
    
    - 可用一个 `probing` 标志或信号量控制。
        
    - 否则多个请求并发探测会导致状态不一致。
        

---

### ✅ 5. 避免在持锁状态下执行用户函数（避免阻塞）

- 外部函数 `fn()` 应该**在释放锁之后执行**：
    
    - 防止执行耗时或阻塞逻辑时导致整个熔断器无法响应其他请求。
        
    - 正确顺序：
        
        go
        
        复制编辑
        
        `cb.mu.Lock() // 检查/更新状态 cb.mu.Unlock()  res, err := fn() // 执行耗时逻辑  cb.mu.Lock() // 根据结果更新状态 cb.mu.Unlock()`
        

---

### ✅ 6. 并发安全

- 所有读写共享状态的操作必须加锁（如 `state`、`failRequest` 等）。
    
- 如果只读、但值可能被其他 goroutine 写，也应考虑加读锁或统一加互斥锁。
    

---

### ✅ 7. 错误定义

- 明确返回 `ErrCircuitBreakerOpen`，表示熔断拒绝了请求。
    
- 可用于调用方判断是否重试、降级、记录告警等。
    

---

### ✅ 8. 可配置性

- 支持超时设置、阈值配置（推荐用 `Option` 模式）：
    
    go
    
    复制编辑
    
    `cb := NewCircuitBreaker(3, 5, WithTimeout(10*time.Second))`
    

---

### ✳️（可选）额外增强点

|增强功能|说明|
|---|---|
|指数退避（backoff）|Open 状态下逐步延长恢复时间|
|滑动窗口统计|替代简单的计数逻辑，提高准确性|
|指标/监控输出|输出当前状态、失败率、成功率等指标|
|熔断后降级策略|提供兜底方案或 fallback|
