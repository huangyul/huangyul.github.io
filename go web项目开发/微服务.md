# grpc

## proto 文件

简单的protp文件模板如下:
```proto
syntax = "proto3";
package "user.v1";
option go_package = "user/v1;userv1";

service UserService {
	rpc GetUser(Req) returns (Resp)
}

Message Req {
	int64 id = 1;
}

Message Resp {
	string username = 1;
}
```
说明点:
- syntax：指明版本号，现在一般都是用3;
- option go_package：前面是文件的路径，后面是go的package;

详细的proto可参考：[官方中文文档](https://protobuf.com.cn/)

## 编译proto文件

### Buf

`Buf` 是一款更高效、开发者友好的 `Protobuf API` 管理工具，不仅支持代码生成，还支持插件和 `Protobuf` 格式化。

#### 安装

如果是macos，使用brew安装
```shell
brew install bufbuild/buf/buf
```

查看是否安装成功

```shell
buf --help
```
#### 使用Buf生成go代码

##### 初始化配置

```shell
buf config init
```

该命令会在根路径下生成一个 `buf.yaml` 文件，修改配置如下:
```yaml
version: v2
deps: - buf.build/googleapis/googleapis:main
modules:
    # 指定proto文件的路径，该路径会影响生成文件的路径
	- path: proto
lint:
	use:
		- STANDARD
breaking:
	use:
		- FILE
```
 **`buf.build/googleapis/googleapis:main` 解释：**
- `buf.build` 是一个 Protobuf 包管理平台，它托管和管理 Protobuf 文件的版本。你可以将其视为 Protobuf 的类似 GitHub 的代码托管平台。
- `googleapis/googleapis` 是一个 **Protobuf 仓库**，包含了 Google 提供的许多公共 API 定义和相关的 Protobuf 文件。这个仓库包含了很多常用的 API 规范，例如 Google 的 gRPC API、Google Cloud API 等。
- `main` 是仓库的 **分支名称**，表示你想要依赖 `googleapis` 仓库的 `main` 分支上的 Protobuf 文件。

##### 初始化代码生成配置
在根目录下新建 `buf.gen.yaml` 
```yaml
version: v2
managed:
  enabled: true
  go_package_prefix:
    default: "githhub.com/huangyul/go-blog/api/proto/gen"
plugins:
  - plugin: buf.build/protocolbuffers/go
    out: api/proto/gen
    opt: paths=source_relative
  - plugin: buf.build/grpc/go
    out: api/proto/gen
    opt:
      - paths=source_relative
```

##### 运行 Buf 生成代码

```shell
buf generate
```

#### 可能遇到的问题

##### 编译次数限制
因为编译需要拉远程的依赖，而 `buf` 官方对于无校验的请求只允许**10/小时**的频率，如果需要解除这个限制：
1. [注册账号](https://buf.build/)
2. 在命令行中实现登录 `buf registry login`，会自动打开浏览器完成登录
