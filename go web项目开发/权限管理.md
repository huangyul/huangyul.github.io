# Casbin

`casbin`是一个强大、高效的访问控制库，支持多种访问控制模型，如`ACL/RBAC/ABAC`等。同时支持多种编程语言。

权限实际上就是控制**谁**能对**什么资源**进行**什么操作**。`casbin`将文芳控制模型抽象到一个基于`PERM`（Policy，Effect，Request，Matchers）元模型的配置文件中：
- `policy`是策略的定义，定义了具体的规则。
- `request`是对访问请求的抽象。
- `matcher`匹配器，将请求与定义的`policy`一一匹配，生成多个匹配结果。
- `effect`根据请求运用匹配器得出所有的结果进行汇总，决定该请求是**允许**还是**拒绝**。

## 模型文件

```model
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[matchers]
m = r.sub == p.sub && r.obj == p.obj && r.act == p.act

[policy_effect]
e = some(where (p.eft == allow))
```

[各种控制模型例子](https://github.com/casbin/casbin/tree/master/examples)
## 策略文件

```
p, dajun, data1, read
p, lizi, data2, write
```

## 简单使用例子

```go
package main

import (
  "fmt"
  "log"

  "github.com/casbin/casbin/v2"
)

func check(e *casbin.Enforcer, sub, obj, act string) {
  ok, _ := e.Enforce(sub, obj, act)
  if ok {
    fmt.Printf("%s CAN %s %s\n", sub, act, obj)
  } else {
    fmt.Printf("%s CANNOT %s %s\n", sub, act, obj)
  }
}

func main() {
  e, err := casbin.NewEnforcer("./model.conf", "./policy.csv")
  if err != nil {
    log.Fatalf("NewEnforecer failed:%v\n", err)
  }

  check(e, "dajun", "data1", "read")
  check(e, "lizi", "data2", "write")
  check(e, "dajun", "data1", "write")
  check(e, "dajun", "data2", "read")
}
```

## RBAC 模型

上面的例子是实现了ACL模型，也就是非常直接的定义了**谁**能对**什么数据**进行**什么操作**，当用户量和资源数量大了之后，权限配置就会非常痛苦。`RBAC（role-based-access-control）`通过引入**角色**这个中间层来解决这个问题。
