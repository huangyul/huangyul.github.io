
# 使用 `wrk` 测试 GET 和 POST 请求
#wrk

#### 1. **安装 `wrk`**

如果你的系统还没有安装 `wrk`，可以参考以下方式安装：

- **macOS (使用 Homebrew)**:
    
    sh
    
    复制编辑
    
    `brew install wrk`
    
- **Ubuntu**:
    
    sh
    
    复制编辑
    
    `sudo apt install wrk`
    
- **源码安装**:
    
    sh
    
    复制编辑
    
    `git clone https://github.com/wg/wrk.git cd wrk make sudo cp wrk /usr/local/bin/`
    

---

#### 2. **测试 GET 请求**

sh

复制编辑

`wrk -t4 -c100 -d30s http://your-api.com/get-endpoint`

- `-t4`：使用 4 个线程
- `-c100`：保持 100 个并发连接
- `-d30s`：测试持续 30 秒

---

#### 3. **测试 POST 请求**

`wrk` 默认是 GET 请求，测试 POST 需要自定义 `Lua` 脚本，例如 `post.lua`：

lua

复制编辑

`wrk.method = "POST" wrk.body   = '{"key": "value"}' wrk.headers["Content-Type"] = "application/json"`

然后执行：

sh

复制编辑

`wrk -t4 -c100 -d30s -s post.lua http://your-api.com/post-endpoint`

---

### **测试结果关注的指标**

`wrk` 的输出结果一般如下：

bash

复制编辑

`Running 30s test @ http://your-api.com/get-endpoint   4 threads and 100 connections   Thread Stats   Avg      Stdev     Max   +/- Stdev     Latency     10.32ms   2.34ms   80.54ms   92.34%     Req/Sec    9402.34    452.12   11021     87.12%   1,128,456 requests in 30.00s, 1.25GB read Requests/sec:  37615.20 Transfer/sec:     41.8MB`

需要关注：

1. **Requests/sec**：每秒请求数（QPS），衡量 API 的吞吐量。
2. **Latency (延迟)**
    - **Avg**（平均延迟）：单个请求从发送到响应的平均时间。
    - **Max**（最大延迟）：最慢请求的延迟，可能代表极端情况。
3. **Req/Sec**（每秒处理请求数）：请求的分布情况，数值稳定说明服务稳定。
4. **Transfer/sec**：数据传输速率，衡量服务器带宽占用。

---

### **分析 & 调优建议**

- 如果 `Latency` 过高：
    - 优化数据库查询（如加索引、缓存）。
    - 增加后端并发能力（如使用 Goroutines）。
    - 使用负载均衡。
- 如果 `Requests/sec` 过低：
    - 可能是 CPU/内存瓶颈，考虑扩展硬件或优化代码。
    - 检查是否有请求队列阻塞或数据库锁问题。
