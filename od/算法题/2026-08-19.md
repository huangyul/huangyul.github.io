# 1. 207. 课程表
## 1. 核心直觉：大学排课与“连环套”死锁

- **生活比喻：**
    
    想象你大学选课，有些高阶课有**先修条件**。
    
    - 比如修《机器学习》前必须先修《线性代数》。
        
    - 如果规则变成：“修《线性代数》要先修《高等数学》，修《高等数学》要先修《大学物理》，而修《大学物理》又要求先修过《线性代数》……”
        
    - 这三门课就形成了一个互相卡脖子的“连环套”（死锁），你一门课都开不了，永远无法毕业。
        
- **术语桥梁：**
    
    - 课程之间的依赖关系构成了一张**有向图（Directed Graph）**。
        
    - 每门课程是一个**节点（Node）**，依赖关系是一条**有向边（Edge）**：$A \to B$ 表示修完 $A$ 才能修 $B$。
        
    - 判断能否修完所有课程，本质就是判断这个有向图中是否存在**环（Cycle）**。若无环，就能排出一个合法的学习先后顺序，这个过程叫**拓扑排序（Topological Sort）**。
        

## 2. 极简流程推导（Kahn 算法 / 入度 BFS）

我们引入一个关键概念——**入度（In-degree）**：表示“当前这门课还有几门先修课没完成”。

> **核心逻辑：**
> 
> 1. 先挑**入度为 0** 的课（没有任何门槛，随时可以上）。
>     
> 2. 上完这门课后，把所有依赖它的后续课程的“门槛计数”（入度）减 1。
>     
> 3. 重复此过程。如果所有课都被上过了，说明没有死循环；如果有课程卡着没法上，说明图中有环。
>     

### 微型示例：4门课（0, 1, 2, 3）

依赖规则：`0 -> 1`，`0 -> 2`，`1 -> 3`，`2 -> 3`（修完 0 才能修 1 和 2；修完 1 和 2 才能修 3）。

|**步骤**|**各课入度表 [课0, 课1, 课2, 课3]**|**可上课程队列 Queue (入度=0)**|**动作**|**已学课程数**|
|---|---|---|---|---|
|**初始**|`[0, 1, 1, 2]`|`[0]`|课0 门槛为 0，入队|0|
|**第1步**|消耗 0，课1和2入度减1：`[0, 0, 0, 2]`|`[1, 2]`|学完课0，解锁课1和课2，均入队|1|
|**第2步**|消耗 1，课3入度减1：`[0, 0, 0, 1]`|`[2]`|学完课1，课3门槛还剩1（课2还没学）|2|
|**第3步**|消耗 2，课3入度再减1：`[0, 0, 0, 0]`|`[3]`|学完课2，课3门槛清零，入队|3|
|**第4步**|消耗 3|`[]` (队列空)|学完课3，队列清空，结束|4|

> **结果：** 已学课程数（4） == 总课程数（4） $\rightarrow$ **返回 true**。

## 3. 击穿思维盲点

### 盲点 1：题目给的输入 `[ai, bi]` 方向到底怎么画？

- **陷阱点：** 题目写着 `[ai, bi]` 表示想学 `ai` 必须先学 `bi`。
    
- **破局直觉：** 谁是因、谁是果？**`bi` 是先决条件，`ai` 是后续课程**。
    
- 因此有向边是 **`bi -> ai`**。即学完 `bi` 才能去解锁 `ai`，所以是 **`inDegree[ai]++`**（`ai` 的门槛 +1），而不是 `inDegree[bi]++`。
    

### 盲点 2：如果出现“环”，算法是怎么识别出来的？

- 假设存在 `A -> B -> A` 的互卡环：
    
    - A 的入度是 1（等 B），B 的入度也是 1（等 A）。
        
    - 初始阶段，A 和 B 的入度都**不为 0**，因此它们**永远进不了队列**。
        
    - 队列提前变空，最终“已修课程数”一定**小于**总课程数 $numCourses$。
        

## 4. 比喻-代码映射（Go 语言实现）


```go
package main

func canFinish(numCourses int, prerequisites [][]int) bool {
	// 1. 构建邻接表 (课程关系网) 和 入度数组 (每门课的门槛数)
	adj := make([][]int, numCourses)
	inDegree := make([]int, numCourses)

	for _, req := range prerequisites {
		curCourse, preCourse := req[0], req[1]
		// 比喻：从先修课连一条路指向后续课
		adj[preCourse] = append(adj[preCourse], curCourse)
		// 比喻：后续课的先修门槛计数 +1
		inDegree[curCourse]++
	}

	// 2. 找到所有“零门槛”的课程（入度为 0）
	// 比喻：把所有不需要前置条件的课放进“待上课程清单”
	queue := make([]int, 0)
	for i := 0; i < numCourses; i++ {
		if inDegree[i] == 0 {
			queue = append(queue, i)
		}
	}

	// 3. 开始按顺序上课 (BFS 拓扑排序)
	learnedCount := 0

	for len(queue) > 0 {
		// 比喻：从清单中取出一门可以上的课修掉
		course := queue[0]
		queue = queue[1:]
		learnedCount++

		// 比喻：修完这门课后，去通知所有依赖它的后续课程
		for _, nextCourse := range adj[course] {
			inDegree[nextCourse]-- // 解除一个先修限制
			
			// 比喻：如果后续课程的所有前置课都修完了，加入“待上课程清单”
			if inDegree[nextCourse] == 0 {
				queue = append(queue, nextCourse)
			}
		}
	}

	// 4. 判断是否全部修完
	// 比喻：如果修完的课数量等于总课数，说明没有被“死锁环”卡住
	return learnedCount == numCourses
}
```


# 2. 200 岛屿数量
### 核心直觉：病毒式“染色拆迁队”

把整张网格想象成一片汪洋大海，`'1'` 是露出水面的陆地，`'0'` 是水。相连的陆地组成了一座岛。

- **地毯式搜索**：你开着直升机从左上角到右下角逐格巡视（双重循环遍历）。
    
- **发现新大陆**：只要你看到一块还没被标记的陆地 `'1'`，说明发现了一座**全新的岛屿**，岛屿计数器 `+1`。
    
- **拆迁/沉岛（DFS 深度优先搜索）**：为了防止之后巡视到这座岛的其他部分时“重复计数”，你立刻派出一支**拆迁队空降到这个点**。拆迁队会顺着上下左右四个方向像病毒扩散一样，把所有**相连的陆地全部推平淹没成水（原地改成 `'0'`）**。等拆迁队把整座岛彻底沉入海底后，你再继续巡视下一个格子。
    

### 走通极简流程

假设有一个 $3 \times 3$ 的微型地图：

Plaintext

```
初始状态:
1  1  0
0  1  0
0  0  1
```

1. 巡视到 `(0, 0)`，发现 `'1'`：
    
    - 发现第 1 座岛，**计数 = 1**。
        
    - 触发拆迁队（DFS），沿相连陆地将 `(0, 0)`、`(0, 1)`、`(1, 1)` 全部变成 `'0'`。
        
    - 地图变为：
        
        Plaintext
        
        ```
        0  0  0
        0  0  0
        0  0  1
        ```
        
2. 继续巡视：`(0,1)`、`(0,2)`、`(1,0)`、`(1,1)`、`(1,2)`、`(2,0)`、`(2,1)` 全都是 `'0'`，直接跳过。
    
3. 巡视到 `(2, 2)`，发现 `'1'`：
    
    - 发现第 2 座岛，**计数 = 2**。
        
    - 触发拆迁队，将 `(2, 2)` 变成 `'0'`。
        
4. 巡视结束，最终得到岛屿数量为 **2**。
    

### 关键盲点解答

- **盲点 1：把陆地改成 `'0'`（原地修改）会不会影响后续判断？**
    
    - **不会，这正是核心技巧。** 将访问过的 `'1'` 改为 `'0'` 等价于打上 `visited` 标记。因为我们只关心“连通块的数量”，一旦一个连通块被完整探索并计数，它在后续的巡视中就失去了作为“新岛屿起点”的意义，直接视为水域即可，还能省下额外 $O(M \times N)$ 的 `visited` 数组空间。
        
- **盲点 2：为什么 DFS 不需要回溯（不需要把 `'0'` 还原回 `'1'`）？**
    
    - 普通的回溯算法（如全排列、N 皇后）是为了寻找所有可能的路径，所以需要“撤销选择”；而图的连通分量遍历是**单向消耗型任务**，目标是把当前连通块内的所有节点一次性访问完毕，绝不能撤销。
        

### Go 代码映射

Go

```
package main

func numIslands(grid [][]byte) int {
	if len(grid) == 0 || len(grid[0]) == 0 {
		return 0
	}

	rows, cols := len(grid), len(grid[0])
	count := 0

	// 角色：直升机地毯式巡视
	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			// 对应比喻：发现未被处理的陆地 -> 确认发现一座新岛屿
			if grid[r][c] == '1' {
				count++
				// 对应比喻：派出拆迁队，沉没整座连通岛屿
				sinkIslandDFS(grid, r, c, rows, cols)
			}
		}
	}

	return count
}

// sinkIslandDFS 即为拆迁队扩散逻辑
func sinkIslandDFS(grid [][]byte, r, c, rows, cols int) {
	// 边界检查：越界、或者是海水('0')，拆迁队停止向该方向扩散
	if r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] == '0' {
		return
	}

	// 对应比喻：推平当前陆地，沉入海底（防止重复访问）
	grid[r][c] = '0'

	// 对应比喻：向上下左右四个方向扩散推平
	sinkIslandDFS(grid, r-1, c, rows, cols) // 上
	sinkIslandDFS(grid, r+1, c, rows, cols) // 下
	sinkIslandDFS(grid, r, c-1, rows, cols) // 左
	sinkIslandDFS(grid, r, c+1, rows, cols) // 右
}
```

- **时间复杂度**：$O(M \times N)$，网格中每个格子最多被访问常数次。
    
- **空间复杂度**：$O(M \times N)$，最坏情况下（整张网格全为陆地）递归调用栈的深度达到网格总大小。

# 3. 198. 打家劫舍

把小偷想象成一个**精明的挑食食客**，街道上的每家房子都是一盘按顺序端上来的菜（数组 `nums`），金额就是热量值。

规则只有一条：**不能连续吃相邻的两盘菜（会触发报警）**。

当你走到第 $i$ 盘菜面前时，大脑里永远只做一次**二选一的权衡（状态转移方程）**：

- **吃这盘（偷当前家）：** 你必须放弃上一盘（$i-1$），收获是“前天为止吃到的最大热量（$dp[i-2]$）+ 今天这盘菜（$nums[i]$）”。
    
- **不吃这盘（放弃当前家）：** 你能保留“直到昨天为止吃到的最大热量（$dp[i-1]$）”。
    

你在每一家门口都取这两者的最大值：$dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$。

**极简流程推演**

以金币数组 `nums = [2, 7, 9, 3, 1]` 为例：

- **第 1 家 ($2$)：** 只有一家，直接偷 $\rightarrow$ **累计收益：2**
    
- **第 2 家 ($7$)：** 比较偷第1家($2$)还是偷第2家($7$) $\rightarrow$ $\max(2, 7) =$ **7**
    
- **第 3 家 ($9$)：**
    
    - 偷第3家：前天收益 $2 + 9 = 11$
        
    - 不偷第3家：昨天收益 $7$
        
    - 取最大值 $\rightarrow$ $\max(7, 11) =$ **11**
        
- **第 4 家 ($3$)：**
    
    - 偷第4家：前天收益 $7 + 3 = 10$
        
    - 不偷第4家：昨天收益 $11$
        
    - 取最大值 $\rightarrow$ $\max(11, 10) =$ **11**
        
- **第 5 家 ($1$)：**
    
    - 偷第5家：前天收益 $11 + 1 = 12$
        
    - 不偷第5家：昨天收益 $11$
        
    - 取最大值 $\rightarrow$ $\max(11, 12) =$ **12**
        

最终最大金额为 **12**（偷第 1、3、5 家）。

**初学者关键盲点**

- **盲点 1：是不是只要隔一家偷一家（比如奇数位全偷、偶数位全偷）就行？**
    
    - **错。** 比如 `[2, 1, 1, 2]`，如果按奇偶偷最多得 $2+1=3$；但最优解是偷第 1 家和第 4 家（中间连续空了两家），收益是 $2+2=4$。动态规划的比较逻辑自然涵盖了“连续放弃两家”的情况。
        
- **盲点 2：为什么不需要开一个大数组记录所有历史？**
    
    - 站在今天的房子前，决策只依赖“昨天为止的最大收益”**和**“前天为止的最大收益”**。大前天的数据已经融合进前天的数据中了，因此只需**两个滚动变量即可把空间复杂度降到 $O(1)$。
        

**Go 代码实现与比喻映射**


```Go
package main

func rob(nums []int) int {
	n := len(nums)
	if n == 0 {
		return 0
	}
	if n == 1 {
		return nums[0]
	}

	// 空间优化：只记录“前天”和“昨天”的最大收益
	prevMax := 0 // 对应比喻中的：大前天的收益（初始为0）
	currMax := 0 // 对应比喻中的：前一天的最大收益（初始为0）

	for _, money := range nums {
		// 比喻映射：
		// 1. 偷当前家：prevMax + money (前天的收益 + 今天的金额)
		// 2. 不偷当前家：currMax (维持昨天的最大收益)
		// 决策：二选一取最大值
		nextMax := max(currMax, prevMax+money)

		// 往后走一家，更新“前天”和“昨天”
		prevMax = currMax
		currMax = nextMax
	}

	return currMax
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```

- `prevMax + money`：对应“吃了今天这顿，就只能加上前天及以前的成果”。
    
- `currMax`：对应“今天这盘菜不吃了，保留昨天的最佳战绩”。
    
- `max(...)`：对应每走到一户门前，**挑食食客做出的局部最优抉择**。

# 4. 169 多数元素

最优解法是 **Boyer-Moore 投票算法**，其核心思想是“不同元素两两抵消”：

- **核心逻辑**：维护一个候选人 `candidate` 和一个计数器 `count`。
    
- **计票规则**：
    
    - 当 `count == 0` 时，将当前元素设为新的 `candidate`。
        
    - 若当前元素等于 `candidate`，则 `count++`。
        
    - 若当前元素不等于 `candidate`，则 `count--`（发生抵消）。
        
- **为什么有效**：多数元素的出现次数严格大于其他所有元素出现次数之和，因此无论怎么抵消，最后留下的必定是多数元素。
    

**Go 语言实现**

Go

```
package main

func majorityElement(nums []int) int {
    candidate := 0
    count := 0

    for _, num := range nums {
        if count == 0 {
            candidate = num
        }
        if num == candidate {
            count++
        } else {
            count--
        }
    }

    return candidate
}
```

**复杂度分析**

- **时间复杂度**：$O(n)$，只需遍历一次数组。
    
- **空间复杂度**：$O(1)$，仅使用两个常数级别的变量记录候选者与计数。
