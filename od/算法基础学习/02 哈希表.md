
**哈希表（Hash Table）通过哈希函数将键（Key）映射到数组下标，从而在平均 **$O(1)$** 的时间复杂度内完成插入、删除和查找。在算法题中，它最常见的三种形态是：**快速映射**、**元素去重** 与 **频次统计**。

### 1. 快速映射 (Key-Value Lookup)

用空间换时间，把内层循环的线性搜索 $O(n)$ 降为 $O(1)$ 的直接映射查找。

**典型例题：LeetCode 1. 两数之和 (Two Sum)**

- **思路**：遍历数组时，对于当前元素 `num`，我们需要寻找的目标差值是 `target - num`。通过哈希表记录已经遍历过的数字及其下标：如果差值存在于表中，直接返回两个下标；不存在则存入当前数值。
    
- **复杂度**：时间 $O(n)$，空间 $O(n)$。
    

Go

```
func twoSum(nums []int, target int) []int {
    // 映射关系：num -> index
    seen := make(map[int]int, len(nums))
    for i, num := range nums {
        complement := target - num
        if idx, ok := seen[complement]; ok {
            return []int{idx, i}
        }
        seen[num] = i
    }
    return nil
}
```

### 2. 元素去重 (Set / Existence Check)

Go 语言没有内置的 `Set` 类型，通常使用 `map[T]struct{}` 替代。`struct{}` 不占用内存（`unsafe.Sizeof(struct{}{}) == 0`），是 Go 中实现纯集合与去重的标准实践。

**典型例题：LeetCode 217. 存在重复元素 (Contains Duplicate)**

- **思路**：维护一个集合，遍历数组，一旦发现当前数字已在集合中，说明存在重复，立即返回 `true`；遍历结束仍无冲突则返回 `false`。
    
- **复杂度**：时间 $O(n)$，空间 $O(n)$。
    

Go

```
func containsDuplicate(nums []int) bool {
    // 使用空结构体实现 HashSet，零内存开销
    set := make(map[int]struct{}, len(nums))
    for _, num := range nums {
        if _, exists := set[num]; exists {
            return true
        }
        set[num] = struct{}{}
    }
    return false
}
```

### 3. 频次统计 (Frequency Counter)

用于计算字符、数字或状态的出现次数。由于 Go 的 `map[key]int` 在访问不存在的 key 时会自动返回该类型的零值 `0`，自增计数代码非常简洁。

**典型例题：LeetCode 242. 有效的字母异位词 (Valid Anagram)**

- **思路**：判断两个字符串是否由完全相同的字符及相同频次构成。先遍历第一个字符串累加频次，再遍历第二个字符串扣减频次。出现负数或长度不等即为无效。
    
- **说明**：小写字母固定 26 个时，工程和刷题中亦可用长度 26 的数组作为高效的定长哈希表；但通用的字符集/哈希表模式如下：
    
- **复杂度**：时间 $O(n)$，空间 $O(k)$（$k$ 为不同字符数）。
    

Go

```
func isAnagram(s string, t string) bool {
    if len(s) != len(t) {
        return false
    }

    counts := make(map[rune]int)
    for _, ch := range s {
        counts[ch]++
    }

    for _, ch := range t {
        counts[ch]--
        if counts[ch] < 0 {
            return false
        }
    }
    return true
}
```

### Go 语言中哈希表的核心注意事项

| **维度**       | **特性与底层原理**                                         | **刷题/工程实践建议**                                             |
| ------------ | --------------------------------------------------- | --------------------------------------------------------- |
| **容量预分配**    | 触发扩容（Load Factor 超过约 6.5）会导致翻倍重建 `hmap` 与渐进式搬迁。     | 预知数据量时显式传参：`make(map[K]V, hint)`，减少扩容开销。                  |
| **Key 的合法性** | 只有**可比较类型（Comparable）**才能作为 Key。                    | 切片（`slice`）、映射（`map`）、函数不能作 Key。字符串、数字、定长数组或可比结构体可作为 Key。 |
| **遍历无序性**    | Go 运行时在迭代 map 时引入了随机偏移量。                            | 永远不要依赖 map 遍历的顺序；若需保序，须额外维护一个记录 Key 插入顺序的切片。              |
| **零值可用性**    | 未初始化的 `var m map[string]int` 读取返回零值，但写入会触发 `panic`。 |                                                           |
