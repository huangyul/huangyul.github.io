
贪心算法（Greedy Algorithm）的核心逻辑可以用一句话概括：**只顾眼前，哪步看起来最划算就选哪步，绝不回头。**

它不考虑长远规划，也不去推算所有可能的分支，而是寄希望于“每一步都选局部最优解，最终能拼凑出全局最优解”。

# 生活中的例子：买东西找零钱

假设你去超市买东西，收银员需要找你 **66 元**，收银台里有 50元、20元、10元、5元、1元 几种面额的纸币。

收银员怎样才能**用最少张数的纸币**找钱？ 正常人都会下意识地采取“贪心”策略：

1. 先挑面额最大的：给一张 **50 元**（剩下 16 元需要找）。
    
2. 再挑能给的最大面额：给一张 **10 元**（剩下 6 元）。
    
3. 再给一张 **5 元**（剩下 1 元）。
    
4. 最后给一张 **1 元**（找齐了）。
    

一共给了 4 张纸币。每一步都挑当前允许的最大面额，这就是最典型的**贪心算法**。

# 贪心算法的核心特征与陷阱

贪心算法好用，但它有一个致命弱点：**并不是所有问题，眼前最优就等于全局最优。**

## 跳跃游戏 (LeetCode 55)

#### **题目描述**：

给定一个非负整数数组 `nums`，你最初位于数组的第一个下标。数组中的每个元素代表你在该位置可以跳跃的最大长度。判断你是否能够到达最后一个下标。

#### 贪心思路拆解

不需要纠结“到底跳 1 步好还是跳 2 步好”，我们只要贪心维护一个指标：**目前能到达的最远距离 `maxReach`**。

1. 遍历数组，每走到一个位置 $i$，首先判断当前位置是否在 `maxReach` 范围内（走不到这里就说明断层了，直接失败）。
    
2. 如果能走到 $i$，就看以 $i$ 为跳板，能把最远距离推到多远：`i + nums[i]`。
    
3. 贪心地更新 `maxReach = max(maxReach, i + nums[i])`。
    
4. 如果 `maxReach` 已经能覆盖最后一个位置，直接返回成功。

#### 实现

```go
func canJump(nums []int) bool {
    safeBorder := 0 // 目前能到达的最远安全边界，开局是 0

    for i := 0; i < len(nums); i++ {
        // 如果当前要看的格子 i，已经超过了我们的安全边界
        // 说明前面没有任何跳法能来到格子 i，彻底断层
        if i > safeBorder {
            return false
        }

        // 站在格子 i 上，最远能跳到 i + nums[i]
        // 看看它能不能把我们的安全边界推得更大
        if i + nums[i] > safeBorder {
            safeBorder = i + nums[i]
        }

        // 安全边界已经盖过或到达最后一个格子的下标了
        if safeBorder >= len(nums) - 1 {
            return true
        }
    }

    return false
}
```

## 分发饼干 (LeetCode 455)

#### 1. 题目在问什么？

你有一群小朋友和一堆饼干：

- 每个小朋友都有一个**胃口值** $g[i]$（比如胃口是 3，必须吃大小 $\ge 3$ 的饼干才会开心）。
    
- 每块饼干都有一个**尺寸** $s[j]$。
    
- 规则：**每个孩子最多只能分一块饼干**。
    
- 目标：**最多能满足多少个孩子？**
    

#### 2. 现实中的贪心直觉

假设有三个孩子，胃口分别是：`[1, 2, 3]`

你手里有三块饼干，尺寸分别是：`[1, 1, 3]`

你怎么分才能满足最多的人？

- 如果你把最大的饼干（大小 3）直接随手塞给胃口只有 1 的小孩，虽然他也满足了，但大饼干被**浪费**了！后面胃口是 3 的孩子就没东西吃了。
    
- 最划算的做法一定是：
    
    - **用最小的饼干，去满足胃口最小的孩子。**
        
    - 大尺寸的饼干要“省着点用”，留给胃口大的孩子。
        

这就是贪心策略：**每次都把当前最小的能吃饱的饼干，喂给当前胃口最小的小孩。**

#### 3. 解题步骤：排个序，双指针挨个对

1. **先排序**：把孩子胃口从小到大排序，把饼干尺寸从小到大排序。
    
2. **拿饼干去试探**：
    
    - 拿最小的饼干，看能不能喂饱胃口最小的孩子。
        
    - 能喂饱：小孩开心了，换**下一个小孩**，也消耗掉这块饼干。
        
    - 喂不饱：这块饼干太小了，这个小孩吃不下，后面胃口更大的小孩更吃不下，说明这块饼干**谁也喂不饱，直接扔掉**，换下一块更大的饼干来试。
        

#### 4. Go 语言实现


```Go
package main

import (
	"fmt"
	"sort"
)

func findContentChildren(g []int, s []int) int {
	// 1. 先把胃口和饼干都从小到大排序
	sort.Ints(g)
	sort.Ints(s)

	childIdx := 0  // 当前正在等喂的小孩
	cookieIdx := 0 // 当前正在拿出的饼干

	// 只要还有小孩没喂，并且还有饼干可用
	for childIdx < len(g) && cookieIdx < len(s) {
		// 如果这块饼干能喂饱当前这个胃口最小的小孩
		if s[cookieIdx] >= g[childIdx] {
			childIdx++ // 小孩吃饱了，看下一个小孩
		}
		// 无论这块饼干有没有喂饱他，它都被用过/排除了，必须看下一块饼干
		cookieIdx++
	}

	// 最终被满足的小孩数量，就是 childIdx 往前推进了多少步
	return childIdx
}
```

## 买卖股票的最佳时机 II (LeetCode 122)
#### 1. 题目在问什么？

给你一个数组 `prices`，其中 `prices[i]` 表示一支股票在第 `i` 天的价格。

- 你可以进行多次交易（可以买入卖出多次）。
    
- **约束条件**：你不能同时参与多笔交易（买新股票前必须把手里的卖掉）。
    
- **目标**：求你能获得的最大利润。
    

#### 2. 人脑直觉与现实贪心

假设未来几天的股票价格是：`[1, 3, 2, 8, 4]`

如果你能“未卜先知”，怎么赚钱最狠？

- 第 0 天 1 块钱买，第 1 天 3 块钱卖，赚 **2 块**。
    
- 第 2 天 2 块钱买，第 3 天 8 块钱卖，赚 **6 块**。
    
- 总共赚：$2 + 6 = 8$ 块。
    

如果价格是一直涨的呢？比如 `[1, 2, 5]`：

- 你可以选择第 0 天买、第 2 天卖，赚 $5 - 1 = 4$ 块。
    
- 你也可以看作：
    
    - 第 0 天买，第 1 天卖（赚 $2 - 1 = 1$）。
        
    - 同一天立刻再以 2 块买入，第 2 天卖（赚 $5 - 2 = 3$）。
        
    - 总利润依然是 $1 + 3 = 4$ 块！
        

###### 贪心大招：化整为零

把跨越多天的长波段利润，拆解为**每一天的微小差价**：

$$prices[3] - prices[0] = (prices[1] - prices[0]) + (prices[2] - prices[1]) + (prices[3] - prices[2])$$

只要明天比今天贵（差价为正），我们就假装“今天买、明天卖”，把这一小截利润装进兜里；只要明天比今天便宜（差价为负），我们就按兵不动。

贪心策略：**只收集所有正向爬升的线段，跳过所有下跌的线段。**

#### 3. Go 语言实现

代码极其清爽，甚至不需要额外的辅助空间：



```Go
package main

import "fmt"

func maxProfit(prices []int) int {
	totalProfit := 0

	// 从第 1 天开始，看它相比前一天有没有涨
	for i := 1; i < len(prices); i++ {
		diff := prices[i] - prices[i-1]
		// 只要今天比昨天贵，这笔差价就一定要赚到
		if diff > 0 {
			totalProfit += diff
		}
	}

	return totalProfit
}
```
