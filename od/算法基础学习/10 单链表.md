
# 基础概念

### 第一步：链表到底是什么？（寻宝游戏模型）

#### 切片（Slice / 数组）与链表的本质区别

- **切片 / 数组**：就像一排**连在一起的储物柜**（编号 0, 1, 2, 3）。因为连在一起，你知道柜子 0 的位置，就能一眼看到柜子 3 在哪里（支持随机访问，下标读取快）。
    
- **链表**：像一场**寻宝游戏**。每个宝箱（节点）分散在房间的各个角落（内存的不同位置）。
    
    - 宝箱里有两样东西：
        
        1. **宝物**（`Val`，节点存的值）
            
        2. **下一张纸条**（`Next`，写着下一个宝箱的内存地址）
            
    - 如果你丢了手里的纸条，后面的所有宝箱就永远找不到了！
        

在 Go 里，宝箱长这样：



```Go
type ListNode struct {
    Val  int       // 当前节点存的数据
    Next *ListNode // 指向下一个宝箱的指针（本质就是一张写着下一处内存地址的纸条）
}
```

### 第二步：小白最容易晕的两个语句（必须刻进骨髓）

初学者最常被以下两句话绕晕，必须彻底区分：

#### 1. `p = p.Next` （移动手指）

- **含义**：你的手指本来指着当前节点 A，现在**把手指移开，指到下一个节点 B 上**。
    
- **效果**：链表本身没有任何变化，绳子没断，只是“你的观察视角往后移了一位”。
    

#### 2. `p.Next = q` （重新系绳子）

- **含义**：改变结构！把当前节点 A 原本指向后面的绳子解开，**重新系到节点 q 身上**。
    
- **致命陷阱**：在解开绳子之前，如果没找别的手抓住 A 原本的后继节点，A 后面的整串链表就瞬间**丢失在内存中**（断链灾难）。
    

### 第三步：为什么老手写代码总带一个 `dummy`（虚拟头节点）？

来看一个最简单的场景：**删除值为 2 的节点**。

#### 没有 dummy 时的尴尬情况：

删除普通节点（比如 1 -> 2 -> 3 删 2），逻辑是：让 1 直接指向 3（`node1.Next = node3`）。 但如果要删的是第一个节点（头节点 head）呢？ 头节点前面根本没有节点！你就必须写一个 `if head.Val == target { head = head.Next }` 单独处理。

#### 有 dummy 时的优雅：

我们在整个链表最前面，人工生造一个“假节点” `dummy`，让它的 Next 指向真正的 `head`：

Plaintext

```
[dummy] -> [head: 1] -> [2] -> [3] -> nil
```

- 无论你要删除、插入哪一个节点（包括原本的 head），**所有节点头顶都有一个“前驱节点”**。
    
- 逻辑完全统一，再也不用为“头节点是不是空的”、“删的是不是第一个”写一堆 `if-else`。
    
- 函数最后只需要返回 `dummy.Next`，就是操作后的真实头节点。
    

### 第四步：逐帧推演经典考题——反转链表（LeetCode 206）

这是所有链表题的根基。目标：把 `1 -> 2 -> 3 -> nil` 变成 `3 -> 2 -> 1 -> nil`。

我们需要三个角色：

- `curr`：当前正在处理的节点（当前宝箱）
    
- `prev`：前一个节点（反转后，当前宝箱应该指向的目标；最开始是 `nil`）
    
- `next`：用来暂存后路的临时变量
    

#### 初始状态

Plaintext

```
prev = nil
curr = 1 -> 2 -> 3 -> nil
```

#### 第 1 轮循环：

1. **留后路**：`next = curr.Next`（把 2 的地址记下来，不然后面找不到 2 了）
    
2. **掉头系绳子**：`curr.Next = prev`（1 的绳子不再指 2，而是指向 prev，也就是 `nil`）
    
    - 此时局部变成：`nil <- 1`
        
3. **手指前移**：
    
    - `prev = curr`（prev 走到 1）
        
    - `curr = next`（curr 走到 2）
        

#### 第 2 轮循环：

1. **留后路**：`next = curr.Next`（把 3 的地址记下来）
    
2. **掉头系绳子**：`curr.Next = prev`（2 的绳子指向 1）
    
    - 此时局部变成：`nil <- 1 <- 2`
        
3. **手指前移**：
    
    - `prev = curr`（prev 走到 2）
        
    - `curr = next`（curr 走到 3）
        

#### 第 3 轮循环：

同理，3 指向 2。最后 `curr` 走到了 `nil`，循环结束。 此时 `prev` 刚好停在 3，**3 就是新链表的头节点**！

#### 对应带详细中文注释的 Go 代码：

```Go
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode = nil // 一开始前面什么都没有，所以是 nil
    curr := head             // 从真实的头节点开始出发

    for curr != nil {        // 只要当前还有节点没处理完
        next := curr.Next    // 第一步：赶紧把下一张纸条存到 next，防止断链找不着路
        curr.Next = prev     // 第二步：把箭头的方向反过来，指向前一个节点
        prev = curr          // 第三步：prev 往前走一步（认领当前节点为新的“上一个”）
        curr = next          // 第四步：curr 往前走一步，去处理下一个节点
    }

    return prev // 循环结束后，curr 变成了 nil，prev 正好停在反转后的第一个节点
}
```

# 经典题目

## LeetCode 92. 反转链表 II 核心笔记

### 1. 核心思想：穿针引线“头插法”

无需断开子链表二次遍历，在 $[left, right]$ 区间内**就地头插**，单次遍历即可完成。

- **现实模型（抽牌）**：固定区间前驱（`pre`），右手按住原区间首节点（`cur`），每次把 `cur` 后面的节点（`next`）抽出来，直接插入到 `pre` 的正后方。
    

### 2. 关键指针与职责

- **`dummy`（哨兵节点）**：指向原头节点，彻底规避 `left = 1` 时头节点被换掉导致的空指针边界问题。
    
- **`pre`**：待反转区间的前驱（位于 `left - 1`），**整个过程位置固定不变**。
    
- **`cur`**：反转区间的第一个节点，**指针指向固定不变**，反转完成后变成区间的末尾节点；其 `.Next` 每次都是下一个待抽取的节点。
    
- **`next`**：每次从 `cur.Next` 抽出来准备插到前面的节点。
    

### 3. 三步穿针引线（重点记忆）

每轮循环做 3 步（执行 $right - left$ 次）：



```Go
next := cur.Next
cur.Next = next.Next   // 1. 摘除：跳过 next，原链表两边缝合
next.Next = pre.Next   // 2. 接后：next 指向当前区间的最新头部
pre.Next = next        // 3. 接前：pre 指向 next，完成头插
```

> **高频易错点：为什么不能写 `next.Next = cur`？**
> 
> - 只有第 1 轮时 `pre.Next == cur`（纯属巧合）。
>     
> - 从第 2 轮开始，`pre.Next` 已经变成了前面刚插进去的节点（如节点 3）。若写成 `next.Next = cur`，新节点会直接跳过中间已反转的节点去连 `cur`，导致中间节点丢失、链表断裂。
>     
> - **`pre.Next` 永远代表当前反转区间的“最前端”**，必须连它。
>     

### 4. 最小核心模板 (Go)



```Go
func reverseBetween(head *ListNode, left int, right int) *ListNode {
    dummy := &ListNode{Next: head}
    pre := dummy
    // 1. 走到 left - 1 的位置
    for i := 0; i < left-1; i++ {
        pre = pre.Next
    }
    cur := pre.Next
    // 2. 头插法反转 right - left 次
    for i := 0; i < right-left; i++ {
        next := cur.Next
        cur.Next = next.Next
        next.Next = pre.Next
        pre.Next = next
    }
    return dummy.Next
}
```
