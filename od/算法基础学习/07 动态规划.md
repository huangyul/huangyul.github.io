
动态规划（Dynamic Programming，简称 **DP**）听起来高大上，但它骨子里其实就一句话：**“记住算过的结果，绝不重复劳动。”**

如果用生活中的例子来打比方：

- 问：$1 + 1 + 1 + 1 + 1$ 等于几？
    
- 答：等于 $5$。
    
- 问：如果在左边再添一个“$1 +$”，现在等于几？
    
- 答：$6$！
    
- 为什么你能瞬间答出来？因为你**记住了**刚才算出的 $5$，只需要拿 $1 + 5 = 6$ 即可，而不需要把这 6 个 1 从头再数一遍。
    

这就是动态规划的核心哲学。

# 一、动态规划到底解决什么问题？

它专门解决**重叠子问题**和**最优子结构**的问题：

1. **重叠子问题**：大问题拆成小问题后，很多小问题是**一模一样**的（比如递归求斐波那契数，同一个 $f(3)$ 会被算成百上千次）。
    
2. **最优子结构**：大问题的最优解，可以由小问题的最优解推导出来。
    
3. **无后效性**：前面的状态一旦确定，就不受后面选择的影响（昨天发生的事已经落定，只影响今天，不会因为你今天做了什么而反向改变昨天的结果）。
    

# 二、解决 DP 问题的“五步心法”

做动态规划题，别急着上手写代码，心里默念这 5 步：

1. **定义状态 (`dp` 数组含义)**：`dp[i]` 到底代表什么？（这一步最关键，定义对了题目解了一半）。
    
2. **找出状态转移方程**：`dp[i]` 怎么从前面的 `dp[i-1]`、`dp[i-2]` 算出来？（找规律/做选择）。
    
3. **确定初始状态（base case）**：最基本、不用算就知道的值是多少？（如 `dp[0]`、`dp[1]`）。
    
4. **确定遍历顺序**：是从前往后推，还是从后往前推？
    
5. **举例推导**：手动算前几个，看看跟公式对不对得上。


# 三、经典入门实战

### 爬楼梯（LeetCode 70）

#一维线性DP

**题目描述**：

假设你正在爬楼梯。需要爬 $n$ 阶你才能到达楼顶。每次你可以爬 $1$ 个台阶或 $2$ 个台阶。你有多少种不同的方法可以爬到楼顶？

#### 1. 拆解思路

- 想要走到第 $n$ 阶，最后一步只有两种可能：
    
    - 从第 $n-1$ 阶跨 **1 步**上来；
        
    - 从第 $n-2$ 阶跨 **2 步**上来。
        
- 那么走到第 $n$ 阶的方法总数，就是**走到第 $n-1$ 阶的方法数 + 走到第 $n-2$ 阶的方法数**。
    
- 公式直接出炉：`dp[i] = dp[i-1] + dp[i-2]`。
    

#### 2. Go 语言标准 DP 实现

```Go
package main

import "fmt"

func climbStairs(n int) int {
	// Base Case: 1 阶只有 1 种走法，2 阶有 2 种走法 (1+1 或 2)
	if n <= 2 {
		return n
	}

	// 1. 定义 dp 数组：dp[i] 表示到达第 i 阶的方法总数
	dp := make([]int, n+1)

	// 3. 初始状态
	dp[1] = 1
	dp[2] = 2

	// 4. 从前往后遍历递推
	for i := 3; i <= n; i++ {
		// 2. 状态转移方程
		dp[i] = dp[i-1] + dp[i-2]
	}

	return dp[n]
}

func main() {
	n := 5
	fmt.Printf("爬 %d 阶楼梯共有 %d 种方法\n", n, climbStairs(n)) // 输出 8
}
```

### 最小路径和（ LeetCode 64.）

#二维网格DP 

#### 1. 题目核心与模型归类

- **模型**：二维网格线性 DP
    
- **规则**：每次只能**向右**或**向下**移动一步
    
- **目标**：从左上角 `(0, 0)` 到右下角 `(m-1, n-1)`，路径上数字总和最小
    

#### 2. 动态规划五步推导

- **第一步：状态定义**
    
    `dp[i][j]` 表示从起点 `(0, 0)` 走到格子 `(i, j)` 的**最小路径和**。
    
- **第二步：状态转移方程**
    
    到达 `(i, j)` 只有两条路：
    
    1. 从上方格子 `(i-1, j)` 向下走一步
        
    2. 从左方格子 `(i, j-1)` 向右走一步
        
    
    取两者的较小值加上当前格子的花费：
    
    $$dp[i][j] = \min(dp[i-1][j], dp[i][j-1]) + grid[i][j]$$
    
- **第三步：初始状态（边界处理）**
    
    1. **起点**：`dp[0][0] = grid[0][0]`
        
    2. **第一行（$i = 0$）**：没有上方来源，只能一路向右走：
        
        `dp[0][j] = dp[0][j-1] + grid[0][j]`
        
    3. **第一列（$j = 0$）**：没有左方来源，只能一路向下走：
        
        `dp[i][0] = dp[i-1][0] + grid[i][0]`
        
- **第四步：遍历顺序**
    
    外层行 `i` 从 `1` 到 `m-1`，内层列 `j` 从 `1` 到 `n-1`，从左到右、从上到下逐格递推。
    
- **第五步：返回值**
    
    终点位置 `dp[m-1][n-1]`。
    

#### 3. 完整 Go 代码实现



```Go
package main

// minPathSum 计算从左上角到右下角的最小路径和
func minPathSum(grid [][]int) int {
	m := len(grid)
	if m == 0 || len(grid[0]) == 0 {
		return 0
	}
	n := len(grid[0])

	// 1. 创建二维 dp 表
	dp := make([][]int, m)
	for i := range dp {
		dp[i] = make([]int, n)
	}

	// 2. 初始化起点
	dp[0][0] = grid[0][0]

	// 3. 初始化第 0 行（只能从左往右走）
	for j := 1; j < n; j++ {
		dp[0][j] = dp[0][j-1] + grid[0][j]
	}

	// 4. 初始化第 0 列（只能从上往下走）
	for i := 1; i < m; i++ {
		dp[i][0] = dp[i-1][0] + grid[i][0]
	}

	// 5. 递推填充剩余网格
	for i := 1; i < m; i++ {
		for j := 1; j < n; j++ {
			dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]
		}
	}

	return dp[m-1][n-1]
}
```

#### 4. 复杂度分析

- **时间复杂度**：$O(m \times n)$，需要完整遍历一次二维矩阵中的所有格子。
    
- **空间复杂度**：$O(m \times n)$，开辟了一个大小为 $m \times n$ 的二维辅助数组记录中间状态。


### 分割等和子集 （LeetCode 416）

#0-1背包

#### 1. 题目翻译：从“子集划分”变身“0-1 背包”

**原题意**：给你一个只包含正整数的非空数组 `nums`，判断是否可以把这个数组分割成两个子集，使得两个子集的元素和相等。

**大白话翻译**：

1. 算一下整个数组的总和 `sum`。如果 `sum` 是奇数，直接返回 `false`（两个整数相加不可能等于奇数）。
    
2. 如果是偶数，目标就是找出一组数，让它们的和恰好等于 `target = sum / 2`。
    
3. **代入 0-1 背包模型**：
    
    - 背包容量：$W = \text{target}$
        
    - 物品：数组里的每个数 `nums[i]`
        
    - 限制：**每个数字只能用 1 次**（这就是 0-1 背包的特征）
        
    - 目标：是否存在一种挑选方案，**恰好把容量为 `target` 的背包填满**？
        

#### 2. 动态规划五步推导（纯二维版本，方便建立直观认知）

- **第一步：状态定义**
    
    `dp[i][j]` 表示：从前 $i$ 个数里任意挑选，是否能凑出总和刚好为 $j$（`true` 或 `false`）。
    
    - 范围：$i$ 从 $0$ 到 $n$（表示前 $i$ 个数），$j$ 从 $0$ 到 `target`。
        
- **第二步：状态转移方程**
    
    面对第 $i$ 个数字（即 `nums[i-1]`），只有选或不选两种可能：
    
    1. **不选第 $i$ 个数**：能不能凑出 $j$，完全看前 $i-1$ 个数行不行：
        
        `dp[i][j] = dp[i-1][j]`
        
    2. **选第 $i$ 个数**（前提是当前容量能装下，即 $j \ge nums[i-1]$）：背包留出放它的空间，看前 $i-1$ 个数能否凑出剩余的容量 $j - nums[i-1]$：
        
        `dp[i][j] = dp[i-1][j - nums[i-1]]`
        
    
    综合两者，只要其中一种成立即可：
    
    $$dp[i][j] = dp[i-1][j] \lor dp[i-1][j - nums[i-1]]$$
    
- **第三步：初始状态（base case）**
    
    1. `dp[i][0] = true`：凑出和为 0，只需一个都不选即可，永远可行。
        
    2. 其余位置初始都为 `false`。
        
- **第四步：遍历顺序**
    
    外层遍历物品 $i$（$1 \le i \le n$），内层遍历目标容量 $j$（$1 \le j \le target$）。
    
- **第五步：最终答案**
    
    `dp[n][target]`：看用全部前 $n$ 个数能否凑出 `target`。
    

#### 3. 二维 DP 的 Go 语言实现

```Go
package main

func canPartition(nums []int) bool {
	sum := 0
	for _, x := range nums {
		sum += x
	}

	// 奇数不可能等分成两个整数子集
	if sum%2 != 0 {
		return false
	}

	target := sum / 2
	n := len(nums)

	// dp[i][j]：前 i 个数能否凑出和为 j
	dp := make([][]bool, n+1)
	for i := range dp {
		dp[i] = make([]bool, target+1)
	}

	// 初始化：容量为 0 时，什么都不选就可以凑出 0
	for i := 0; i <= n; i++ {
		dp[i][0] = true
	}

	// 开始递推
	for i := 1; i <= n; i++ {
		num := nums[i-1] // 当前物品的大小
		for j := 1; j <= target; j++ {
			if j < num {
				// 容量不够，装不下当前数，只能不选
				dp[i][j] = dp[i-1][j]
			} else {
				// 装得下：不选 OR 选
				dp[i][j] = dp[i-1][j] || dp[i-1][j-num]
			}
		}
	}

	return dp[n][target]
}
```

#### 4. 0-1 背包最关键的延伸考点：一维空间压缩（倒序遍历）

面试中 0-1 背包一般都会要求压缩到一维切片。如果你观察转移方程：

$$dp[j] = dp[j] \lor dp[j - num]$$

计算新的 $dp[j]$ 时，依赖的是**上一轮**更小容量的 $dp[j - num]$。

- **如果正序（从左向右）遍历**：算大容量时，前面的小容量已经被**本轮的新值**覆盖了，导致同一个数字被重复使用多次（这就变成完全背包了）。
    
- **如果倒序（从右向左）遍历**：算大容量时，左边的小容量依然是**上一轮保留下来的旧值**，保证每个数字只被使用一次。
    

**一维优化版本代码**：

```Go
func canPartitionOptimized(nums []int) bool {
	sum := 0
	for _, x := range nums {
		sum += x
	}
	if sum%2 != 0 {
		return false
	}
	target := sum / 2

	dp := make([]bool, target+1)
	dp[0] = true

	for _, num := range nums {
		// 核心：倒序遍历背包容量，只要 j >= num 即可
		for j := target; j >= num; j-- {
			dp[j] = dp[j] || dp[j-num]
		}
	}

	return dp[target]
}
```
